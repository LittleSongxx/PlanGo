- [完整协议](../../docs/质量评测协议.md)：TSR二元验收、事实切分/判分、分母、来源时效、金标复核、数据划分和统计口径。
- [任务草案](tasks.dev.json)：12条、6个家族。`agent_input`仅存用户输入；`environment`是评测器配置，不能直接作为模型提示词。
- [金标草案](gold.dev.json)：每条任务的must-pass、禁止结论、事实依据与可接受变体。全部由AI起草、待人审，不传给被测模型。
- [来源登记](sources.dev.json)：3份既有原始材料的文件/子树hash与2类显式受控材料。路径位于私有output，未复制数据库、profile或Cookie。只有注册的原始子树可作为候选来源，旁边的系统生成结果不可当gold。
- [静态检查记录](design-check.json)：12条任务/金标草案与3份原始子树hash核对通过；人审/留出/模型运行数量均为0，不产生质量分数。
- [划分计划](split-plan.json)：30条留出尚未采集、3条实时哨兵尚未执行；没有把旧门店改名成未见集。
- [任务评分空表](task-annotations.csv)、[事实评分空表](claim-annotations.csv)：没有填造分数。

原始来源人工审核、独立金标与未见留出仍待完成。尤其原始DOM文本的120/32元只保留相邻数字，不能推断原价标签；公交raw响应尚缺完整请求时间元数据。当前程序的解析结果不负责填补这些缺口。任务草案中的 `readiness_blockers` 保留设计时记录，runner实施状态以本文与当次manifest为准。

以下命令只检查**设计文件结构和来源hash**，不会运行Agent或生成质量分数：

```bash
python3 scripts/check_quality_design.py
```

`design_valid=true`不等于`evaluation_ready=true`。在缺少私有原始文件的克隆中，检查会报告来源不可用并保持未就绪；如本地来源存在但hash改变，则报错。

## 运行与复核

本仓库已有依赖即可运行，不安装新框架。使用本项目独立 `plango` Python；默认只预检，不发模型请求。

```bash
/home/song/miniconda3/envs/plango/bin/python scripts/quality_runner.py
# 把刚输出的source_sha原样填入；源文件/任务/gold/编译产物变化则拒绝执行
/home/song/miniconda3/envs/plango/bin/python scripts/quality_runner.py --run-dev --source-sha SHA
```

`--cases DEV-05,DEV-06` 可预先选择范围，必须按相同范围重新预检。每次使用新的私有 `output/quality-v1/` 目录，保留旧失败，不覆盖旧尝试。`--offline-wiring` 使用无密钥退化路径，仅验证接线，绝不产生Agent质量成绩。

- 8条读取/范围任务：真实模型与API、冻结原始观测注入；没有重放真实DOM、视觉或商家网络，不能称完整浏览器端到端测试。
- DEV-05/06：显式导入未保存的受控规范与单店草案，然后通过真实消息API修改；高德/天气/供给来自公开声明的受控fixture，未知项不补造。
- DEV-09/10：同样的导入初态，实际Electron操作保存、重开或消息送达核对；代理必须取得真实202接受后才丢响应。DEV-09另单独重启自有后端，桌面重启与后端重启分别记录。
- 原始观测时间与题目业务时间分开；业务时钟适配不冻结SQL租约、执行deadline或超时。模型沿本项目配置，额外串行限制为每例12次、整批80次模型调用。120000已报告tokens是下次调用前的停止阈值，单次请求可能跨过该累计阈值；缺usage/账户异常会停止并保留缺口。
- 只有配置的模型出口允许异步HTTP；桌面只允许自有动态回环API。真实商家网络、交易和外部消息均不在执行范围。主数据库/profile与兄弟项目不参与。

每题留下输入、初态/轮次/末态的独立SQLite读取、持久事件、助手回复与实际React卡片渲染文字、工具回执、用量和失败原因。桌面任务还保留故障中间停点的原快照/UI文字/截图；历史停点没有即时SQL时明确标空，不拿末态冒充。

```bash
# 默认只打包复核材料，零judge调用；输出目录必须不存在
/home/song/miniconda3/envs/plango/bin/python scripts/quality_review.py \
  --collection output/quality-v1/RUN/collection.json --output output/quality-v1/REVIEW
# 添加 --run 才调用本项目模型做有界AI辅助标注，仍待人工复核
```

评分器按全部must-pass与禁止项计算TSR，按原子事实计算任务宏平均Groundedness；不读产品phase当分数。缺输出、来源定位、覆盖标注或可裁决证据均保留pending，零事实为N/A。重复尝试须显式说明invalid原因与替代关系，不能选最高分覆盖失败。AI标注不能改写为人工通过。

- [可复核来源包](source-packets.dev.json)：原始子树投影与哈希，真实/受控来源分开。
- [自动可核验条件](oracle-checks.dev.json)：目前仅6项状态检查可自动核对，其余语义/轨迹判断保留待审。
- [人工复核指南](../../docs/质量评测人工复核.md)：盲化材料、原子事实标注与分歧处理。
- `scripts/quality_scoring.py`：对已完成标注的结构化JSON做确定性聚合；缺标注不能生成完整成绩。

正式简历数字仍需要独立来源人审与预先封存的新留出集；30条留出和3条实时哨兵尚未运行，不能将这12条熟悉任务改名充当盲测。
