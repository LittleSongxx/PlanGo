# PlanGo 真实桌面用户流程验收

2026-09-09。本目录使用实际 Electron/React/WebContentsView、真实高德和已配置模型，连接独立 `plango-e2e` PostgreSQL/Redis/API/worker（本机 18011）与独立桌面 profile。主用户数据不用于增删测试；不运行完整质量指标测评。脚本驱动鼠标、键盘、文件与窗口，状态验收读取真实 API。`actions.json` 保留动作与发现；普通 host 截图不会包含原生 WCV，外部网页的系统截图见 `../plango-live-browser/`。

## 已验证的用户路径

- 手动输入完整重庆观音桥地名，调用真实高德地址解析，保存坐标/来源/粒度；真实附近 5 公里 POI、图片和价格返回，路线弹窗调用真实高德。
- 选择实际 POI 创建持久任务，澄清输入和后续修改通过聊天提交；具体规划失败及修后复验见下节。
- 分享固定方案快照，另一真实 Chromium 以手机宽度打开，投票和留言传回桌面，用户点击并入后形成新的任务输入。重启桌面后原分享和反馈仍存在。
- 手机分享页保留草案未核验说明，缺图保持空态。明确注入 HTTP503/网络中断时不显示保存成功；恢复请求后投票和留言可保存。故障注入属于受控辅助验证，不能称真实供应商故障。
- 模型配置面板执行真实“保存并检查连通”成功，保持原接口/模型；该面板不宣称修改独立 Docker 后端环境。
- 明确偏好通过界面保存，提醒通过界面创建，技能通过开关停用；桌面重启后均恢复。提醒删除、明确偏好删除经真实 API 保存。
- 对真实失败任务提交“需改进”，反馈持久存入 PostgreSQL；记忆面板显示明确反馈范围，可逐条删除。删除后任务结果同步取消已保存标记，桌面/API重启不复生，原任务仍在历史。
- 停止隔离 API 后界面显示离线，修后启动 API 自动恢复；原澄清 interrupt 保留，事件序号 1–12 完整且不重复。
- 数据连续性独立核验：迁移前原 SQL 仅恢复到隔离 PostgreSQL 的临时数据库，与主 PlanGo 逐行摘要比较，16 张表原始行全部保留；临时数据库已删除。主 profile 49 条 Cookie、身份和回执原字节保持一致，用户融合文档原 SHA256 不变。见 `original-data-continuity.json`、`desktop-data-continuity.json`。

## 发现与保留的失败

1. 模糊“重庆观音桥”解析成巴南区的另一同名地点。设置提示现显示实际匹配地址/区/粒度，用户能检查结果；完整地名已验证正确位置。不通过硬编码地名替换高德结果。
2. run `4b923f7b92a94fa589fe723c249f3cd0` 选中重庆寿司郎后，门店名被误当起点而全局编码到香港；后续“步行街8号”被误当不完整距离限制，澄清反复出现。原失败保留，canonical选店/起点/距离语义修复后的完整用户链仍需重走。
3. run `d998fab816a7424c8f0784fbf654544b` 请求步行 2 公里，却使用驾车路线 4.5 公里。草案展示了违约说明，尚未进入业务执行；后端已补交通模式与就近选择，待新部署复验。
4. 上述 run 在用户阅读分享并返回后，人工等待被计入运行 300 秒上限而失败（累计 6530 tokens、6 次工具调用）；不是模型预算耗尽。现已持久记录人工暂停并给新用户文本独立有界额度；累计用量保留，定向重启与崩溃恢复检查已过。
5. 第一次 SSE 断线复验后，服务恢复但相同版本快照被去重，界面一直离线；已补首次恢复推送。第二次真实停/启API已通过，事件完整。
6. 第一版记忆删除后服务端已删除，但任务反馈标记仍保留；记忆变更后统一刷新当前快照，实际 UI 删除→标记清除→重启无复生已复验。
7. 分享页旧黄色样式、库存图、未展示未知项、发送失败仍成功、手机输入溢出均已修。旧分享标题仍是当时存下的旧方案文案，保留快照内容；新规划默认标题已改为用户可读。

外部政府网页、图片文件选择器、浏览器导航/停止/标签/历史流程另见 `../plango-live-browser/README.md`。准备表单链另见 `../plango-live-preparation/README.md`，未完成部分不得记为商家履约成功。最终修后规划/准备链证据将在完成后更新本报告。
