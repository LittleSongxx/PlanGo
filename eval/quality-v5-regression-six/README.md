## v5 暴露的实现缺陷（已修）

v5 的独立审核发现**四题根本没拿到受控资料**（`available_at_checkpoint_ids` 为空、`tool_call_count` 为 0），其中 NEW-01、NEW-14 以「模型服务不可用，请检查运行服务中的配置」终止——而模型其实正常返回过。

根因是任务决策的 schema 把「同一次里既给答案又给算式」这种**可恢复的输出形状**整个拒掉；适配器按同一 schema 重试一次后回退到 fallback，`decide_task` 把 fallback 当成供应商不可用，于是整轮任务以配置故障收场。这是本轮语义规则清理时改写提示词引发的，改写让模型更倾向于一次算完再答。

修复分两步，均已提交：

- `8953ffa`：可恢复形状改为规范化（算式在场就当作 calculate 步；交付上挂的浏览器步骤直接丢弃），只有真正不可用的输出仍拒绝。
- `2ece22e`：结构化校验失败不再冒充供应商故障，改为 `DecisionNotUsable` 并作为部分完成上报，保留已读到的资料与计算结果。
