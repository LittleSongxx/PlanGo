# 评分器 v1.4 修订记录（2026-09-12）

v1.3 报告与 dataset 一律不动；v1.4 的重评写成 **新文件名**（`*-llm-v1.4.json`）。

## 1. 改了什么：合同层的 non-factual 家族扩到「页上没有这一项」

`faithfulness.py` 的句子分类器（送评委之前那一层）原来只认
`未知|无法确定|资料未写明|当前值未知|没有写明|未公布`。v3 的 unknown 层刻意去掉了页上的
「未写明」提示语，产品于是用另一种说法报告同一个缺口：

> 当前页面仅显示「荨溪油坊的展陈分三个展区，都在一层」，**未包含**营业时间或关门时间信息，因此今天几点关门未知。

这句话里的「未知」在**同一句**里，所以整句按老词表本应判为 non-factual——但产品把缺口说明写成了
**不带「未知」的独立分句**（`…未显示排队人数或取号状态；`、`且无其他来源提供该数据，因此无法得出…结论。`），
那些分句既不在词表里、又推不出，于是整条断言进分母、被评委判 unsupported。

v3-r2 报告（`holdout-v3-report-r2-llm.json`）unknown 层因此是
**F=0.167，39 条断言只有 7 条 supported**——回答正确的题拿 0 分。这不是产品的问题，是合同层漏了一类句子。

v1.4 按同一原则补两类，且不放松 any 口径：

| 组 | 词 | 附加条件 |
| --- | --- | --- |
| 推理族 | `无法得出` `无法推算` `无法判断` | 无（与既有的 `无法确定` 同类：说自己得不出结论，不是断言事实） |
| 缺口族 | `未包含` `未提供` `未标注` `未给出` `未列出` `未显示` `未记录` `未提及` | 必须与指称本次观测的词同句出现：`页面/资料/记录/告示/公示/快照/观测/文本/菜单/说明` |

第二个条件是精度闸门：光写「未包含」可能是在描述某份记录的内容（例如「须知未包含押金条款」是
关于须知的断言），那种句子仍留在分母里。

评委提示词同步加了一句：这类句子通常由合同层先归为非事实；若仍送到评委，按非事实处理，
**不要为了凑标签判 unsupported**（判 unsupported 会把分母做大、分数做低）。

## 2. 影响面（可复算）

- v1/v2 的题面靠页上「未写明/未核对」提示语触发老路径，v1.4 的词表是**超集**，
  所以那些批次的口径不变；`dataset_sha` 全程不变。
- 该改动只可能让**句子离开分母**，不可能把 unsupported 变成 supported；
  受影响最大的是 v3 的 unknown/conflict 两层。
- 重评产物：`output/trustworthy-v1/holdout-v3-report-{r1,r2,r3}-llm-v1.4.json`（新文件名，旧报告不动）。

## 3. 仍然存在的限制

1. 分类靠词表 + 观测指称词，仍是**文本判据**，不是语义判据；换一批说法（例如「只字未提」）
   还会漏。真正稳的做法是让产品在结构化输出里声明「本条是缺口说明」，成本较高，未做。
2. 扩词表会改变历史分数。本次**没有**重评 v1/v2 全部批次来省调用；若要把 v1.4 当成唯一口径，
   必须把 v1/v2 的四份 attempt 也重评一遍，否则不同报告不可直接比。
3. `substance_min`（v3 的 TSR 检查）与 F 的分母是两件事：前者要 ≥12 实义字符，
   后者看句子标签。只回「未知」两字在两边都会掉分。
