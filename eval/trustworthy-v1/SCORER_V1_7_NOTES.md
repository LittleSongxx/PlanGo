# 评分器 v1.7 修订记录（2026-09-13）

v1.6 及更早的报告与 attempts 一律不动；v1.7 评分写新文件名。

## 1. 改了什么：用户本轮原话进入合法观测

v4 首测实证（`holdout-v4/RESULTS-r1.md`「评分器缺口」）：答复「3名大人和1名小孩的门票
一共是226元。」里 3/1 来自问句，不在观测 → 合同层按编造杀掉，F=0。用户自己说的数字
不是编造——与产品侧 `_stated_by_user` 同一原则。

v1.7 在评分时把 task 的 `user_turns` 以「用户本轮原话（用户自述数字视为给定）」块追加进
观测（`faithfulness.with_user_turns`，pack 拷贝），合同层数字闸门与 LLM 评委同时可见。
两种 turn 形状（字符串 / `{role,text}`）都接受。

## 2. 验证与影响面

- 单测：turn 追加、空 turn 不动 pack、操作数+计算器数字同时到达评委而非死在合同门。
- **这是有意的判据变更，F-only**：rules 对照下逐题差异全部是「答复复述用户数字」的
  calculate 题（v3-r5 +15 题、v2 首跑 +28 题、v4-r1 +8 题，均 0→1.0）；
  TSR 完全不变。
- 旧批次若要与 v1.7 对话需重评（新文件名）；既有 v1.4–v1.6 报告保持原样、原结论不回改。

## 3. 语义边界

- 用户原话只对「数字不判编造、句子可被评委支持」开放；不改变未知/冲突词表、
  不改变 TSR、不改变「页上数字不得单独祝福整句发明」的评委纪律。
- 极端情形：答复捏造了用户没说的数字仍会被拦（用户原话里没有该数字）。
