# 产品修订与 v3 复测（2026-09-12 第三轮）

本文记录本轮从「问法族拆分」得到的诊断、改了什么共享路径、以及复测数字。
**性质：受控开发集测量**（holdout-v3 在实现流里生成、金标未独立审），不得称为未见泛化成绩。
旧产物一律未改动，新跑/新评都用新文件名。

## 1. 诊断：分数跟着问法走，而不是跟着能力走

`holdout-v3` 故意混用问法：calculate 层 `index % 7 ∈ {1,3,5,6}` 是新问法，
persist 层偶数 index 是新问法，conflict/unknown 全部去掉页上提示语。
第一趟（r1，产品代码 `a7ccd0b` 附近的一棵脏树，见 RESULTS-r1.md 的溯源注记）结果是：

| 族 | TSR |
| --- | --- |
| calculate · 沿用词表（合计/一共） | 14/14 = 1.000 |
| calculate · 新问法（两场合买/卡里还能用/全程要走多长时间/退回来多少） | 7/20 = 0.350 |
| persist · 沿用词表（关了再开/重启） | 17/17，F 1.000 |
| persist · 新问法（退出程序再进来/重新进入程序） | 17/17，F 0.346 |
| conflict / unknown（无提示语） | 39/68 = 0.574 |

同一批题、同一批状态，只换问法就掉一半——这是词表覆盖，不是能力。原因在两处共享路径：

- `backend/plango/graph.py` 的 `_REOPEN_TURN = 关掉|重启|重新打开|关了再开` 决定「这是不是确认卡还在」；
- `backend/plango/task.py` 的 `_COMPUTE_ASK = 一共|还剩|合计|加起来|拿回|要多久` 决定「要不要走计算器」。

## 2. 改了什么

### 2.1 确认卡：从「关开动词」改成结构化判据（`graph.py`）

`_asks_if_current_card_holds(state, req)` 现在的判据是：有已接受的卡、本轮不新开行程、
不要新起点、且**稀疏提案没有陈述任何新的卡片值**。`unknown` 标志只是重申卡里没有该值
（用户问的正是这件事），不算修改；用户明确要求清空（`clear_*`）算修改；
`refresh_sources=True`（要求重读页面）优先于复述卡片；已经在准备表单的运行不在范围内。
`_without_card_echo` 只丢掉「模型把刚读过的同名地点又写一遍」这种回声。

这一步让 persist 的复述不再依赖「关掉/重启/重新打开/关了再开」是否出现在问句里。

### 2.2 计算器：从「问法词表」改成结构化判据（`task.py`）

`_derived_answer(answer, context)` 现在问三件事，都不读问法：

1. 答案里的数字，有没有**任何一条来源记录和任何一轮用户话都没写过**的？
   （页上没有、用户也没说的量，是计算器该产出的量。）
2. 页上只列了分项、没写合计，而答案给了合计？（`_arithmetic_derivation`：同一句话里
   两个数做加减乘除得到答案里的数。）
3. 用户自己写过的数字（含澄清轮里回给用户的那个数）视为用户输入，不触发计算器。

页上写了这个数、或者用户写了这个数，都算「读回来的值」，不强制计算器。

### 2.3 「未知」要写成句子（`task.py`）

`RECORDED_VS_CURRENT` 原来写「答复须含字面「未知」……不能只写这两个字」，r1 有 26/68、
r2 有 19/68、r3 有 28/68 的 conflict/unknown 交付就是**光秃秃两个字**（没有任何工具调用）。
指令现在描述**答复形状**：一个完整句，先结论、句中出现「未知」二字、再写清是资料缺该值
还是记录互相冲突。

### 2.4 runner：冻结页必须是 current 源（`scripts/trustworthy/runner.py`）

`frozen_page_state` 只给 artifact 填了 `artifact_id/type/source/data`，而 observation 带
`snapshot_id/url`。产品的 `task_context` 靠这两个字段判断「这条来源是不是当前页」，
于是**整个 204 题批次的页都是 stale**：`_page_in_hand()` 为假，交付提示词以为手里没有页，
而页文其实被塞在用户消息里。补上观测自带的身份字段后实测：

| 题 | 修前 | 修后 |
| --- | --- | --- |
| `h3-calc-001` 扣完之后退回来多少？ | 交付正确但 `answer_number=None`，TSR 失败 | 走 `calculate`，`answer_number=153`，通过 |

这是 runner 的第二个同源缺陷（第一个是 `a7ccd0b` 的命令字段摊平）。

## 4. 仍然没解决的（照实写）

1. **r5 的最终数字**：见 §5（本轮最后一次干净测量）。
2. **calculate 层仍会失败**，原因是评分合同与题库设计的冲突，不是产品不会算：
   v3 的页文把合计算在自己旁边（「日场 45 元。夜场 67 元。两场合买 112 元。」），
   而 oracle 要求 `delivery.answer_number` 来自计算器。产品交付的数字**全对**，
   但没有走工具。不看问法就无法区分「把 45 和 67 加起来」与「陈述两条事实」——
   而看问法正是本轮删掉的东西。要么让这一层的题页不再写出合计（题目改动，需版本化重评），
   要么接受这层分数里含一部分合同口径。
3. **conflict/unknown 的「光秃秃未知」**：指令改成描述答复形状后仍在出现（r3 28/68）。
   这是模型行为波动，不是产品分支问题；再改措辞属于往提示词里堆话。
   结构化的做法是产品侧拒收纯标记并要求重答，但那会把 v3 的 `substance_min` 阈值
   抄进产品，属于为评测加规则，本轮没有做。
4. **F 的非事实词表仍是文本判据**：v1.4 用「缺口词 + 观测指称词」把
   「当前页面未包含…」这类句子移出分母（见 SCORER_V1_4_NOTES.md），
   换一批说法（「只字未提」）还会漏。
5. **金的独立审阅仍未做**：v3 只能叫 `provisional_holdout`；
   审阅要另开会话，用 `holdout-v3/GOLD_REVIEW_PROMPT.md`。
