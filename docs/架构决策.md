## ADR-002：保留 Electron，演进浏览器承载与执行层

状态：WebContentsView、经实测的Playwright/CDP与只读Vision已落地；坐标动作尚未实现，真实商家能力仍须按任务验证。范围与失败见 实施进度 和 浏览器适配验证。

1. 保留 Electron 与 React 桌面工作台。Electron 是适合本项目的成熟桌面方案；具体 webview API 的风险不代表需要替换 Electron。
2. 浏览器承载层逐步采用 WebContentsView，处理窗口尺寸、焦点、视图切换和生命周期。
3. 优先采用适配验证通过的 Playwright 能力；Electron 特有控制缺口再用受控 CDP 补足。Playwright/CDP 是执行层，不能替代上层业务契约。
4. 用户看到的页面、模型观察的页面、执行器操作的页面必须属于同一个受控浏览上下文，保留真实登录会话与人工接管。
5. 采用 DOM-first：语义定位、正确 frame、开放 Shadow DOM、有界等待优先；视觉按需用于理解、消歧、无法结构化表示的目标定位或动作后核验。
6. 视觉目标能映射回 DOM 时优先用 DOM 动作；否则需校验截图时间、页面、裁剪、缩放及坐标映射后再操作。
7. DOM 和 Vision 使用同一命令、授权、幂等、回执及后验规则。拒绝授权、旧审批失效、登录/验证码接管和提交结果 UNKNOWN 不得通过切换视觉绕过或重放。
8. 原始任意脚本/调试协议权限不直接交给模型；固定操作与授权边界应由受信执行层持有。

采用顺序：浏览器会话接管验证 → 成熟 DOM 执行与连续操作 → 按需视觉能力 → 相同任务集下 DOM-only/hybrid 的质量、误操作、接管、延迟与用量对照。

依据与约束见 闭环与设计成熟度评审。后续项目全量替换审计中的库选型、状态/记忆/评测方案仍是待评估建议，不因出现在报告中就成为已确认决策。
