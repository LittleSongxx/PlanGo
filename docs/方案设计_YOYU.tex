\section{一句话：小悠是干嘛的}

\begin{keybox}{一句话讲清楚}
临时想"这周末带娃/陪老婆/陪爸妈出去转转"，但不知道去哪、懒得挨个查、约人又费劲、到店还怕踩雷。\textbf{小悠就是帮你把这件事一句话搞定}：它是一个装在你电脑上的浏览器，你说一句"周六下午带孩子出去玩4小时、老婆减脂、人均120"，它就自己去点评/高德把真店、真路线、真评价查出来，一次给你三套方案，还能帮你点菜、排号、发家人确认。用得越多它越懂你，到周末还会主动问你要不要安排。

\section{我们是怎么设计的（技术方案）}

这一章讲"设计逻辑"：整体怎么分层、记忆怎么建、多 Agent 怎么分工、规划这条链路怎么跑、工具怎么调、出错了怎么兜。设计时我们特意对齐了美团技术团队的两条公开思路——\textbf{WOWService 的多智能体协同（Agents-as-Tools）}和 \textbf{LongCat / VitaBench-2.0 里 Agentic Memory（主动维护用户档案，而非被动检索历史）}，并落到了可运行的代码里。

\subsection{总体架构：五层，各司其职}
从上到下五层，上层只依赖下层的稳定接口，任何一层可单独替换（比如把数据层从高德换成企业自有 API，上面三层不用动）。

\subsection{记忆系统：让它"越用越懂你"}
本地生活的数据天生私密又高价值——你在哪、家在哪、和谁出门、口味禁忌、消费力、作息。行业里把记忆分成\textbf{短期（工作记忆）}和\textbf{长期（跨会话画像）}两层；我们在长期这层进一步拆成\textbf{三级语义金字塔}，思路和"L0 对话 → 结构化事实 → 用户画像"一致：底层留原始证据、顶层供快速调用，且\textbf{每一层都可溯源、可删除，不做不可逆的黑盒摘要}。

\textbf{（1）短期记忆}：主 Agent 每轮把最近 6 条对话按滑动窗口带入，并\textbf{每轮动态重建 System Prompt}——把"当前时间/城市/已知偏好/已装技能"实时注入，避免长上下文里"中间被遗忘"。

\textbf{（2）长期记忆的写入与增强（重要性加权）}：同一条偏好被再次提及时，不是简单覆盖，而是\textbf{证据数 +1、强度上调}（封顶 1.0）；只有强度 $\geq 0.5$ 的高置信偏好才会进入 System Prompt 参与决策。这对应行业里"被多次提及/高置信才固化"的双阈值思路。

\begin{tcolorbox}[colback=black!4,colframe=black!30,left=4pt,right=4pt,top=2pt,bottom=2pt,fontupper=\scriptsize\ttfamily]
// Layer 2: reinforce a preference (repeat -> +evidence, +strength; not overwrite)\\
addPreference(text) \{\\
\ \ if (exists) \{ existing.evidence\_count += 1;\\
\ \ \ \ \ \ \ \ \ \ \ \ \ \ existing.strength = min(1, existing.strength + 0.15) \}\\
\ \ else preferences.push(\{ text, strength: 0.6, evidence\_count: 1 \})\\
\}
\end{tcolorbox}

\textbf{（3）长期记忆的沉淀（Agentic Memory / RewriteMemory）}：我们不做"把历史一股脑塞回上下文"的暴力堆砌，而是用 LLM \textbf{主动地}把零散偏好碎片\textbf{合并去重、压缩成不超过 60 字的稳定画像}（对齐 VitaBench-2.0 里 Agentic Memory 的做法）。失败则静默降级，用原有画像。

\begin{tcolorbox}[colback=black!4,colframe=black!30,left=4pt,right=4pt,top=2pt,bottom=2pt,fontupper=\scriptsize\ttfamily]
// Layer 3: RewriteMemory -- LLM compresses fragments into a stable profile\\
async rewriteMemory() \{\\
\ \ summary = await LLM(sys="merge \& dedup prefs -> <=60-char stable profile",\\
\ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ input=preferences)  // keep only high-confidence, long-lived\\
\}
\end{tcolorbox}

\textbf{（4）读取与主动召回}：规划/点菜/推荐时，画像与高置信偏好被自动带入（记得"老婆减脂"就默认按减脂过滤，不用你重复说）；打开应用时还会用画像生成一句"想起你"的开场（见第 1 页主界面的黄色卡片）。

\textbf{（5）本地 + 可控}：整棵记忆树以明文 JSON 落在你自己电脑的 userData 目录，\textbf{可查看、可删单条、可一键清空}，不上传服务器。这是隐私底线，也是用户敢把真实生活交给它的前提。

\subsection{多 Agent 协同：主-子分工，Agents-as-Tools}
单个大模型在"又要找玩乐、又要挑餐厅、又要上网查攻略、又要沉淀记忆"这种复合任务里容易顾此失彼。我们采用\textbf{层次化多智能体}：主 Agent（小悠本体）负责全局对话控制与决策，把专业活\textbf{当成"可调用的工具"}派给专用子 Agent——这正是 WOWService 的 \textbf{Agents-as-Tools} 范式；子 Agent 干完只回"结论摘要"给主 Agent（即 \textbf{Handoff}：任务 + 上下文一次性交接、再一次性回收）。

设计上三条硬约束保证它稳：\textbf{(1) 工具子集隔离}（每个子 Agent 只拿本职工具，餐饮 Agent 拿不到浏览器）；\textbf{(2) 只读}（子 Agent 一律不做写操作，下单/取号只能由主 Agent 走两步确认）；\textbf{(3) 上下文隔离 + 可并行}（各跑独立 Harness Loop、noHistory，互不污染，能同时找玩乐和餐厅）。整个派单-回收过程在右侧"执行过程"里\textbf{透明可见}（如第 2 节第 3 张图）。

\begin{itemize}[leftmargin=1.3em,itemsep=1pt]
  \item \textbf{人群约束是结构化"真理源"}：每个 persona（减脂/带娃/陪长辈/约会…）都定义了\textbf{硬排除标签、软偏好标签、检索关键词}。硬约束直接进 Verifier（如"减脂"硬排除火锅/烧烤/自助/甜品；"带娃"硬排除酒吧/密室），软偏好只影响排序。persona 可像技能一样插拔扩展。
  \item \textbf{抗污染漏斗（去水分）}：对候选店做\textbf{贝叶斯收缩}（评分向先验均值收缩，证据越少收缩越狠）→ \textbf{刷量团伙降权} → \textbf{流行度去偏}，把"近满分但真实经营信号很少"的可疑店打到后面，并给出"可信/已去水分"的理由。
  \item \textbf{生成即校验 + 定向重生}：Verifier 是\textbf{确定性代码}（非 LLM），逐条查预算、人群硬约束、场景互斥、带娃适龄、营业时间、时序。命中硬伤就只\textbf{换掉出问题的那个节点}（从候选池取下一个合规项），最多 2 轮，收敛快、可解释。
  \item \textbf{五维确定性打分}：省钱/好玩/便捷/合适/特色，全部用方案里的\textbf{真实数据}算（人均 vs 预算、真实评分、段间车程…），\textbf{可复现、与雷达图严格对齐}，每一维都给一句自然语言理由。
  \item \textbf{三套差异化且互斥}：经济（最省）/ 均衡（去水分榜首）/ 特色（高分出片），共享一次检索、跨方案不重复门店。雨雪天自动把户外活动降级为室内。
\end{itemize}

\subsection{工具调用链路（赛题交付物之一）}

\subsection{异常处理机制（赛题交付物之一）}
真实世界一定会满座、售罄、超时、风控。我们的原则是\textbf{"错误即信息，绝不返回空、绝不假装成功、绝不编造"}，落成四道防线：

\toprule
防线 & 做法 \\
\midrule
工具级 ToolHarness & 每个数据/工具调用统一包 超时(12s) + 重试(指数退避) + 降级默认值 + 来源标注；失败不抛崩，返回带 error 的结构 \\
模型级 自纠 & 工具报错被转成文字回喂给模型（"满座/超时"），模型据此主动给备选/改时段/换品类 \\

再加两条"诚实边界"：营业时间等信息\textbf{拿不到就标"建议态"而不是猜}；一切写操作两步确认、且提供 \textbf{cancel\_action} 让计划有变时撤销。这既是工程稳健，也是评审里"技术成熟度/稳定性"的直接体现。

\subsection{主动关心与微信 24h 陪伴}
主动引擎借鉴"随机脉冲 + 时段"机制：每 60s 一次脉冲，只在\textbf{饭点/周末等 DPVP 合适时段}、以较低概率发声（避免打扰），话术只用\textbf{本地行为数据 + 记忆}生成（"记得你喜欢 X，这周再约一次？"）。取号/预约后会往\textbf{提醒队列}塞一条"该出发了"。连上微信后，主动关心\textbf{同步推送到微信}——人不在电脑前也能被惦记，这就是"24h 陪伴"。

\subsection{技术栈}

\subsection{我们在四个评审维度上的亮点}
\begin{itemize}[leftmargin=1.3em,itemsep=1.5pt]
  \item \textbf{创新性}：不做"又一个聊天框"，而是把 AI 放进\textbf{真能操控网页的浏览器}里（Set-of-Marks 可视化操作）+ \textbf{Agentic 本地记忆}（越用越懂、主动关心）+ \textbf{数据留本机}的隐私范式。切入角度是"帮你把事做完"而非"给你一堆链接"。
  \item \textbf{完整性}：从需求理解 → 多 Agent 规划 → 抗污染 → 生成即校验 → 可落地执行（取号/外卖/送花/发家人）→ 记忆沉淀，是一条\textbf{闭环}；错误有四道兜底，稳定性有保障。
  \item \textbf{应用效果}：一句话即可触发，右侧"执行过程"透明可见；结果基于\textbf{高德实时 + 大众点评真实榜单}，并主动去水分；预算/来源\textbf{绝对诚实}，超预算就说超了多少。
  \item \textbf{商业价值}：站在美团生态\textbf{之上}放大 GTV——把"逛-比-订-约-履约"串成一次完成，天然带动到店/团购/外卖/跑腿；本地记忆带来\textbf{高频复访与用户忠诚}；Adapter + 技能 + persona 可插拔，易向企业/垂类扩展。
\end{itemize}

\section{隐私：数据留在你自己电脑}
本地生活的数据其实很私密——你在哪、家在哪、和谁出门、消费力、作息。云端聊天机器人天生要把数据传到服务器；小悠不一样：\textbf{你的登录态和口味记忆都只存在你这台电脑上}（像你平时用 Chrome 一样），明文可查、可删，不上传我们的服务器。花钱的动作一律两步确认。这既是隐私保护，也是让用户敢把真实生活交给它的信任基础。
