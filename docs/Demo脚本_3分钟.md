# PlanGo — 3 分钟 Demo

主线：从当前页面取得有来源的信息，展示价格和未知项，再说明保存草案、仅准备与业务完成的区别。当前实现见 [设计文档](设计文档_PlanGo.md)，启动方式见 [README](../README.md)，本轮真实复验进度见 [实施进度](实施进度.md)。三分钟是讲解安排，不保证外部页面或模型在该时限内完成。

## 演示前准备

- 启动 Electron 与 PlanGo 后端，页面演示时在真实可见浏览器打开已实测可读的菜单或商家页。需要登录时由本人完成，保留当前来源地址。普通高德行程规划可从空浏览器开始，不以先打开网页作为前提。
- 复杂页面抽取与价格比较需要可用模型。行程与地图使用本项目高德配置，并核对实际起点与地区；默认重庆不能当作用户已经确认的精确出发地址。不要展示密钥。
- 预演同一页面、相同请求；记录实际出现的结果。不要预置虚构偏好、订单、排队号或出行足迹。
- 如使用本地网页样本，开场明确说“这是本地测试页面，用来展示解析与交互”；样本价格只说明该样本的计算结果。测试命令和历史报告不能充当真实站点演示。

## 现场流程（合计 180 秒）

### 0:00–0:20：说明工作台与当前页面

展示浏览器里的页面和地址。

话术：“PlanGo把网页、对话和结果放在一个工作台里。先看它从当前页面实际读到了什么，再决定下一步。”

### 0:20–1:00：读取菜单或商家事实

输入：“读取当前页面的真实菜单，保留价格和来源；没有价格的项目请标未知。”

在结果中核对一项名称、价格及原文来源；若页面没有菜单，说明当前读取结果和缺失项。展示可见页面与实际任务步骤；技术讲解可说明“集中工作流加浏览器观察/操作循环”，不把步骤标签当作自治多专家协商的证据。

### 1:00–1:40：按证据算价，展示未知边界

若预演页面含两家商家明确的人均价，输入：“比较当前页面这两家餐厅，2 人，总预算 150 元，列总价、预算是否满足和差额。”商家名称按页面填写。

核对人数、价格口径、乘法与来源。页面只有套餐价、未知价或缺少另一家时，展示无法完整比较的原因。菜单页面没有两家可比商家时，继续核对菜单未知项并查看来源，不临时编造比较数据。

### 1:40–2:15：修改要求，观察新一轮结果

在已成功比较的同一任务里输入：“总预算改为 180 元。”核对商家和人数保留、价格来源与新结论；不承诺每次预算修改都重搜所有地点。人工等待不应耗尽执行时间，新用户编辑的有界额度与累计用量分别保留。

若前一步仅完成菜单抽取，可改为：“继续读取当前页面下面的菜单。”展示页面与观测变化。遇到登录或验证码就暂停，解释人工完成后继续的入口，不演示绕过限制。

### 2:15–2:45：解释审批与结果核实

在预演过的页面展示待确认动作卡，核对目标页面、元素和参数；现场可拒绝或取消。若展示行程草案，明确“保存草案”得到 `draft_ready`，仍带未知项；“仅准备表单”需另行核验，达到 `ready_to_review` 也没有提交。没有已通过预演的准备场景时，只说明入口与边界，不发起真实交易凑流程。

话术：“草案保存只表示安排已经留好，准备完成只表示表单可供核对。写操作仍需确认；页面变化会让旧确认失效。业务结果不确定就保留 UNKNOWN，不会重复提交，也不会只看‘成功’两个字就声称已下单。”

### 2:45–3:00：收尾

回到来源卡和任务历史。

话术：“这次能核对的是屏幕实际展示的读取、计算或草案结果。当前真实准备链仍在复验，取号、预约提交、支付和微信接入也要分别验收。”

## 预演通过后可替换的片段

- **行程**：使用明确地区、起点、日期、人数、时长和预算，展示候选、真实路线或标明的直线下界、未知项；同一任务中改预算/日期、保存草案。不承诺固定三套、每次可执行或已完成商家业务。
- **分享**：分享当前方案的固定版本，在同一局域网手机投票；电脑需保持运行、手机能够访问分享地址。它是网页分享，不是微信机器人。
- **提醒**：显式创建未来提醒，展示待触发状态。只读用户设定文本，不加入没有来源的“还剩两桌”等实时信息。
- **截图**：识别用户提供的截图，明确标记用户来源和识别限制，不直接声称截图中的价格当前有效。
- **记忆**：展示明确保存的偏好或有来源的任务记录，并演示删除后刷新。评分不会自动变成偏好，历史结果不能证明当前营业或履约。

## 失败时怎样继续

模型或网络不可用就展示真实错误与已取得的页面证据；第三方页面阻挡读取就暂停、人工接管或结束该段。需要换本地受控页面时重新声明样本身份。取消失败操作，不用模拟订单、模拟微信消息或数据集回退制造完成结果。

历史结果见 [融合实现与质量验证](融合实现与质量验证.md)，本轮失败与复验以实施进度为准。现场成功一次只证明当时这一个页面与请求；本轮不做完整质量指标测评，也不能把局部演示当成全项目完成。
