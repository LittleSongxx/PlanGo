# PlanGo — 3 分钟 Demo

主线：选门店与优惠，在同一任务修改需求，核对有来源的适用性，保存草案并在中断后继续。当前实现见 [设计文档](设计文档_PlanGo.md)，启动方式见 [README](../README.md)。三分钟是讲解安排，不保证外部页面或模型在该时限内完成。

## 演示前准备

- 启动 Electron 与 PlanGo 后端，页面演示时在真实可见浏览器打开已实测可读的菜单或商家页。需要登录时由本人完成，保留当前来源地址。普通高德行程规划可从空浏览器开始，不以先打开网页作为前提。
- 复杂页面抽取与价格比较需要可用模型。行程与地图使用本项目高德配置，并核对实际起点与地区；默认重庆不能当作用户已经确认的精确出发地址。不要展示密钥。
- 预演同一页面、相同请求；记录实际出现的结果。不要预置虚构偏好、订单、排队号或出行足迹。
- 如使用本地网页样本，开场明确说“这是本地测试页面，用来展示解析与交互”；样本价格只说明该样本的计算结果。测试命令和历史报告不能充当真实站点演示。

## 现场流程（讲解约 180 秒）

只展示一个原任务：**选门店/优惠 → 改人数日期预算 → 看依据 → 保存 → 中断继续**。先预演并记录实际耗时，现场使用已有原任务继续；未完成的步骤如实展示停点，不新建任务补成功。

### 0:00–0:35：门店和优惠来自哪里

打开该任务的优惠比较卡，展示一次实际读取的原文、售价/面值、来源时间及缺失规则。在“选用此优惠”入口核对网页与高德的分店名称和地址，进入同一任务。若资料已过期，说明需要重新核对，不能将历史卡片当今天的商家保证。

### 0:35–1:10：修改同一份需求

使用需求卡改人数、日期和预算，也可展示预演过的自然语言修改。对比修改前后字段，指出门店与优惠引用保持、版本变化；含糊预算应停下来澄清并保留原规范。未指定字段不应随修改清空。

### 1:10–1:45：结论是否有依据

展示优惠适用性、费用范围和未知项。选取一个有来源的数值进行口算核对，区分售价、券面值、人均和全体费用。两人套餐与三人同行的冲突、额外收费或营业规则缺失应明确出现；不能只读一个来源图标就声称判断正确。

### 1:45–2:20：保存当前版本

在实际出现的草案停点点击“保存草案”。核对原任务、计划版本与所选优惠，指出仍然保留待核验项。保存只交付安排，不提交预约，不查询可能锁位的接口，不隐含授权准备表单。

### 2:20–3:00：中断后继续原任务

关闭并重开本次演示的桌面，进入原任务，核对保存版本、字段、来源和聊天轮次。如果出现“已接收·待取回”或“送达待核实”，只核对原请求；不重新发送未知写入，也不重置累计预算。恢复耗时超过讲解窗口时完整保留录屏，不剪成即时成功。

话术：“模型理解用户的修改；程序负责版本、来源、预算与授权。可保存、可恢复的是这份带未知项的草案，商家业务是否完成需要独立回执。”

## 预演通过后可替换的片段

- **行程**：使用明确地区、起点、日期、人数、时长和预算，展示候选、真实路线或标明的直线下界、未知项；同一任务中改预算/日期、保存草案。不承诺固定三套、每次可执行或已完成商家业务。
- **分享**：分享当前方案的固定版本，在同一局域网手机投票；电脑需保持运行、手机能够访问分享地址。它是网页分享，不是微信机器人。
- **提醒**：显式创建未来提醒，展示待触发状态。只读用户设定文本，不加入没有来源的“还剩两桌”等实时信息。
- **截图**：识别用户提供的截图，明确标记用户来源和识别限制，不直接声称截图中的价格当前有效。
- **记忆**：展示明确保存的偏好或有来源的任务记录，并演示删除后刷新。评分不会自动变成偏好，历史结果不能证明当前营业或履约。

## 失败时怎样继续

模型或网络不可用就展示真实错误与已取得的页面证据；第三方页面阻挡读取就暂停、人工接管或结束该段。需要换本地受控页面时重新声明样本身份。取消失败操作，不用模拟订单、模拟微信消息或数据集回退制造完成结果。，本轮失败与复验以实施进度为准。现场成功一次只证明当时这一个页面和请求；质量成绩以 `eval/trustworthy-v1/` 体系为准，不能把局部演示当成全项目完成。
