# PlanGo · PlanGo — 3 分钟 Demo

主线：从当前页面取得有来源的信息，展示价格和未知项，再说明哪些操作需要确认、哪些结果仍待核实。当前实现依据见 [设计文档](设计文档_PlanGo.md)，启动方式见 [README](../README.md)。

## 演示前准备

- 启动 Electron 与 PlanGo 后端，在内置浏览器打开已实测能读取的菜单或商家页面。需要登录时提前由本人完成；保留当前来源地址。
- 复杂页面抽取与价格比较需要配置可用模型。若选演示行程与地图，还需配置高德 Web/JavaScript Key 并核对位置。
- 预演同一页面、相同请求；记录实际出现的结果。不要预置虚构偏好、订单、排队号或出行足迹。
- 如使用本地网页样本，开场明确说“这是本地测试页面，用来展示解析与交互”；样本价格只说明该样本的计算结果。测试命令和历史报告不能充当真实站点演示。

## 现场流程（合计 180 秒）

### 0:00–0:20：说明工作台与当前页面

展示浏览器里的页面和地址。

话术：“PlanGo把网页、对话和结果放在一个工作台里。先看它从当前页面实际读到了什么，再决定下一步。”

### 0:20–1:00：读取菜单或商家事实

输入：“读取当前页面的真实菜单，保留价格和来源；没有价格的项目请标未知。”

在结果中核对一项名称、价格及原文来源；若页面没有菜单，说明当前读取结果和缺失项。展示浏览器观测和任务步骤，不把步骤标签介绍成已验证的多专家协同。

### 1:00–1:40：按证据算价，展示未知边界

若预演页面含两家商家明确的人均价，输入：“比较当前页面这两家餐厅，2 人，总预算 150 元，列总价、预算是否满足和差额。”商家名称按页面填写。

核对人数、价格口径、乘法与来源。页面只有套餐价、未知价或缺少另一家时，展示无法完整比较的原因。菜单页面没有两家可比商家时，继续核对菜单未知项并查看来源，不临时编造比较数据。

### 1:40–2:15：修改要求，观察新一轮结果

在已成功比较的同一任务里输入：“总预算改为 180 元。”查看任务保留商家和人数、重新观测后的价格与结论；只陈述屏幕实际呈现的结果。

若前一步仅完成菜单抽取，可改为：“继续读取当前页面下面的菜单。”展示页面与观测变化。遇到登录或验证码就暂停，解释人工完成后继续的入口，不演示绕过限制。

### 2:15–2:45：解释审批与结果核实

在预演过的安全页面展示待确认动作卡，核对目标页面、元素和参数；现场可拒绝或取消。没有合适页面时用界面入口说明，不发起真实交易来凑流程。

话术：“写操作要先确认；页面变了，旧确认可能失效。点击完成以后还要核对业务结果，不确定就显示待核实。它不会因为看见‘成功’两个字就声称已经下单。”

### 2:45–3:00：收尾

回到来源卡和任务历史。

话术：“这次演示能核对的是页面读取、价格计算和任务过程。真实取号、预约、支付、微信接入还需要分别验收。”

## 预演通过后可替换的片段

- **行程**：使用明确城市、出发点、人数、时长和预算，展示实际返回的候选、路线和警告；不承诺固定三套或每次都有可行方案。
- **分享**：分享当前方案的固定版本，在同一局域网手机投票；电脑需保持运行、手机能够访问分享地址。它是网页分享，不是微信机器人。
- **提醒**：显式创建未来提醒，展示待触发状态。只读用户设定文本，不加入没有来源的“还剩两桌”等实时信息。
- **截图**：识别用户提供的截图，明确标记用户来源和识别限制，不直接声称截图中的价格当前有效。

## 失败时怎样继续

模型或网络不可用就展示真实错误与已取得的页面证据；第三方页面阻挡读取就暂停、人工接管或结束该段。需要换本地受控页面时重新声明样本身份。取消失败操作，不用模拟订单、模拟微信消息或数据集回退制造完成结果。

原始质量结果与失败案例见 [融合实现与质量验证](融合实现与质量验证.md)。现场成功一次只能证明当时这一个页面与请求，不能作为生产成功率。
