# 小念 · AI 本地生活浏览器 — 设计文档（赛题06）

> 一句话：登录你真实账号、能自己操控美团/点评页面的 AI 本地生活管家，把「周末这几个小时」从规划到执行一条龙替你办明白。

## 一、Planning 策略（规划即校验，绝不返 0 方案）

采用 **规划与校验分离 + 约束 by construction**（对标 Tripnostic / NutriOrion），主 Agent「小念」用 LongCat 做 LLM-as-Controller，`plan_outing` 工具内置 5 阶段确定性流水线：

1. **意图解析**：LongCat function-calling 把自由话解析成结构化槽位（城市/人数/预算/时长/出发时间/人群/饮食/兴趣）。缺关键槽位（人数/预算）时主动反问；解析失败用规则兜底 `inferPersonas`。
2. **人群硬/软约束**：`persona.ts` 9 类人群（减脂/带娃/约会/陪长辈/商务/独处/解压/待客/经期），硬排除标签直接进 Verifier，软偏好 + 检索词进检索。人群做成可插拔 **Skill**（`skills/<id>/SKILL.md`，渐进披露）。
3. **并行取供给 + 抗污染排序**：子 Agent 并行查 玩乐(到综)/餐厅(到餐)/天气；数据经 **防腐层 `converter.ts`** 统一成 `POISummary`；`antiPollution.ts` 做贝叶斯收缩去水分 + 团伙降权 + 流行度去偏 + 软偏好加权重排。
4. **组装时间线**：活动(2h)→正餐(1.5h)→加场(1.25h)，高德四模式路线串接，算人均、五维评分（费用/趣味/便利/契合/特色）、「为什么」推荐理由、发同行人文案。
5. **生成即校验 + 定向重生**：`verifier.ts` 逐条查 预算/人群硬约束/场景互斥/带娃适龄/营业状态/时序；有硬失败则**只换犯规的那一站**（≤2 轮），其余不动。

**绝不返 0 方案（3 级降级）**：精确匹配 → 放宽软约束重搜 → 放宽品类兜底；营业时间不可得标「建议态」而非瞎猜（诚实边界）。

**群体确认闭环**（移植 weplan）：`create_consensus` 发确认卡（同意/改一处/拒），`refine_plan` 用**一句话手术刀**改一站（换餐厅/换玩乐/更便宜/提前/推后/去加场/钉住），派生字段自动刷新。

## 二、工具调用链路（Harness Loop + Agents-as-Tools）

`while` 式 Harness Loop（对标 Claude Code）：**动态 System Prompt**（注入时间/城市/记忆/已装技能）→ LongCat 决定调工具 → 执行回喂 → 直至最终答复；`MAX_TURNS` 兜底，工具输出截断防爆上下文。

- **工具分层（官方风格 `@is_tool` READ/WRITE + JSON Schema）**
  - READ（自动执行）：`plan_outing / search_nearby_poi / get_weather / check_availability / recommend_dishes / compare_deal / refine_plan / create_consensus`
  - WRITE（强制两步确认）：`make_reservation / take_queue_number / send_gift / send_message / batch_execute`
  - 浏览器：`browser_navigate / read_page(DISTILL set-of-marks) / extract(Horsepower 表格) / click / type / scroll`
- **专家子 Agent（Agents-as-Tools，只读、上下文隔离、可并行）**：`dining_agent / activity_agent / research_agent(Horsepower 式搜攻略汇总)`，各跑独立 Loop、限定工具子集、只回摘要（对标美团 WOWService）。
- **DPT 快慢思维**：读操作 System1 直接跑；写操作 System2 → 生成确认卡 → **停下等用户确认**（幻觉下单率 0，>¥100 二次提醒）。危险页面动作（取号/支付/下单）同样强制两步确认。
- **企业可改 API（Adapter 模式）**：Agent 只认稳定 Tool Schema，底层 `IDataSourceAdapter` 热插拔 `Mock(VitaBench) / AmapLive(高德) / Enterprise(企业自有/美团 To-A)`，配置 `DATA_SOURCE` 一键切；对齐扣子「上传 OpenAPI 即接入」。

典型链路（家庭场景）：
`plan_outing`(并行 dining_agent+activity_agent+get_weather → 去水分 → 组装 → 校验重生) → `compare_deal` → `recommend_dishes` → `create_consensus` → 用户改一处 `refine_plan` → `batch_execute`(并行 预约+取号+送花，两步确认) → 回执 + 发家庭群。

## 三、异常处理机制（评分分水岭）

- **错误即信息**：工具失败转成文字喂回 LongCat 自纠，不崩循环。
- **ToolHarness**：统一 超时 + 重试(指数退避) + 降级 + **来源标注**（real/dataset/simulated/fallback）。
- **三类真实世界 fallback**（Mock 带随机失败率演练）：满座/排队>90min → 备选/改时段/换品类；商家休息 → 查同类替换；工具超时 → 重试 → 标「信息获取中」区分实时/估算。
- **断网兜底**：高德失败自动切 VitaBench 数据集快照，honest 标 `simulated`。
- **两步确认**：所有 WRITE 工具确认率 100%、幻觉下单率 0。

## 五、边界（讲不演）
跨城旅游/机票酒店/多日行程、完整多人 A2A 谈判、真实微信长连接与真实核销（需平台风控授权）——核心接口已预留（微信 iLink Bot / To-A Adapter），现场不强求演示成功。
