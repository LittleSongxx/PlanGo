This is an isolated real Electron/Xvfb probe against synthetic loopback fixtures. No production profile, model, merchant task, service, repository dependency or root lockfile was modified. Temporary dependency: playwright-core 1.63.0 under this directory. Electron is the repository-installed 33.4.11 / Chromium 130.0.6723.191. The Playwright library was used directly because this task tests Electron target attachment and the proposed programmatic driver API; no Playwright Test framework was introduced.

## Findings and minimal adapter

1. `chromium.connectOverCDP(..., {noDefaults: true})` attaches both shell and persistent-partition WebContentsView pages. Do not select `pages()[0]` or identify by URL: get `Target.getTargetInfo` through `context.newCDPSession(page)`, then compare `webContents.fromDevToolsTargetId(targetId)` to the exact manager-owned WebContents object. A page URL can be duplicated or changed by navigation.
2. Ordinary locator click/fill, successive click→fill→submit, cross-origin `frameLocator`, open shadow-root semantics, and re-rendered disabled→enabled input replacement all work. Native Electron mouse input and Playwright observe the same counter and form. Zoom 1.25 on a 1.5 display also passes Playwright click/fill plus native focus/input after measured CSS→DIP conversion.
3. Playwright 1.63 locator `AbortSignal` cancellation works: abort a waiting click, subsequently reveal the button, and no late click occurs. This only demonstrates cancellation before dispatch; a business submission already dispatched must still become UNKNOWN or be verified through the Harness receipt policy.
4. Cookie and localStorage survive navigation, CDP disconnect/reconnect, and complete Electron restart in `persist:plango-probe`, with the same storage directory. The HTTP server sees the stored fixture cookie on the first request after restart; no cookie copying/importing was used.
5. After `forcefullyCrashRenderer`, retaining the old Playwright Page after native reload fails. Native reload followed by CDP disconnection/reconnection and fresh exact-target lookup recovers the original WebContents/session. Production must invalidate old snapshot refs and command generations; this probe never resumes a side effect.
6. `setWindowOpenHandler.createWindow` returning a newly created WebContentsView stalls this Electron/CDP combination, including when attachment/layout is deferred. The stall also prevents subsequent recovery probes, whose failures remain recorded. Letting Electron create a visible native BrowserWindow with explicitly shared `session` works: Playwright popup event, owner-target lookup, and shared cookie all pass. Initial production adaptation should preserve such native popups instead of claiming arbitrary popup→WCV embedding works. Tab manager metadata can include the popup WebContents; OAuth/opener flows were not tested.
7. Electron main can discover its own endpoint without stderr interception or a proxy: read `app.getPath('userData')/DevToolsActivePort`, combine its port and browser path with loopback, and validate `/json/version`. The 5/5 probe actually connects using the main-discovered endpoint. In production, wait for a current-process file and validate the path against the live version response to reject stale files after crash. Keep endpoint and CDP capability only in the trusted main process.

## Screenshot and pointer calibration

Measured at native view bounds 960×650 DIP, zoom 1.25, `innerWidth=768`, `innerHeight=520`, `devicePixelRatio=1.875`:

| Method | Observed pixels | Verdict |
| --- | --- | --- |
| Playwright screenshot `scale: css` | 614×416 | Wrong, shrunk by zoom again |
| Playwright screenshot `scale: device` | 1152×780 | Wrong, shrunk by zoom again |
| Guest `webContents.capturePage()` | 1440×975 | Correct viewport × measured DPR |
| Raw CDP `Page.captureScreenshot`, no clip, `captureBeyondViewport:false` | 1440×975 | Correct viewport × measured DPR |

Use guest-native capture for the first production driver. Snapshot metadata must preserve content/view identity, CSS viewport, DPR, Electron zoom, view DIP bounds, scroll, clip, and capture time. Check dimensions against the measured values and refuse stale/changing geometry. Do not apply a guessed correction factor to Playwright screenshots.

For a fixed CSS test marker at (40,40) with size 80×80, independently measured `viewBounds.width / innerWidth = 1.25` equals Electron's `getZoomFactor()`. A native DIP clip at approximately (50,50), size 100×100 produces **150×150 pixels, 100% exact marker color** after two animation frames. This verifies position as well as size. Native pointer clicks on a distant small target similarly pass after CSS→DIP conversion; direct Playwright locators use CSS coordinates and need no manual scaling. Floating geometry is rounded only at pixel/DIP API boundaries.

## Ownership split proposed for production

- `src/main/browserDriver.ts`: trusted Playwright attachment, exact-target mapping, current snapshot references and page/form version checks, bounded locator operations, native calibrated capture. Proposed export supplied by parent: `executeBrowserOperation(contents, command, {signal, check, owner, epoch})`.
- Tab/view manager: BrowserWindow/WebContentsView ownership, layout/focus/visibility, partition, navigation/new tabs/popups, lifecycle/crash events. Renderer sends constrained intents and bounds, never arbitrary JS/CDP.
- Existing `browser-bridge.ts`: command fingerprints/cache/queue, cancellation, owner/tab binding, approval/snapshot contracts and UNKNOWN policy. Reuse its boundary instead of creating another scheduler.

Not covered: production integration, arbitrary merchant pages, closed shadow roots, CAPTCHA/login flows, visual model quality, popup→WCV embedding, multi-monitor/OS compositor differences, or cancellation of an already-dispatched business write. These must not be inferred from the fixture results.
