# PlanGo 独立试用记录

本轮修复版待打包、待独立试用；既有 `plango-0.1.0-linux-x64-booking-preview.tar.gz` 绑定旧源码，不含本轮统一需求、资料分析和Electron升级。实际包名、revision、`source_dirty`及内容摘要以待测包内`trial-release.json`和SHA256为准，不能把源码检查算作已测试安装包。安装、配置、诊断、停止及保留数据的方法见[试用安装](试用安装.md)。

本单尚未有独立试用结果，请由未参与开发的实际使用者填写。独立上下文AI审核、开发自动化和受控Cookie兼容检查均不计入真人独立试用；真实商家完整准备/履约同样尚未完成。

只需使用自己的模型/高德配置；不要把密钥、完整 `.env`、浏览器 profile 或冷备份交给他人。配置页中的“执行服务”对应任务后端，桌面连接测试不能代替服务模型测试。

## 开始前

- 记录系统版本、包 revision、开始时间和试用者代号；不要记录真实手机号或账号密码。
- 多个项目同时运行时，一次只打开一个 PlanGo；先检查内存余量。已有安装使用原升级入口，不清库、不换 profile 来恢复失败任务。
- 按[安装说明](试用安装.md)核对包 SHA256、独立安装、填写配置、运行 `doctor` 并启动。
- 在“连接与能力”核对实际执行服务和模型，再由本人点击一次“测试服务模型”。失败原样记录，不能用桌面测试成功替代。

## 三个实际任务

使用者自己决定地点、日期、人数与预算；以下是操作顺序，不是预先填好的成功结果。

| 任务 | 本人操作 | 应核对什么 |
| --- | --- | --- |
| 1. 安排一次出行 | 明确出发点、人数、日期/时段和预算，生成草案；在需求卡改人数或预算，再保存 | 使用自己的真实出发点；搜索半径和单段路程独立；旧条件未丢失，费用与未知项可读；修改有对应回复 |
| 2. 读取门店优惠 | 打开本人愿意查看的真实门店网页，要求只读店名、地址及优惠；有报价时核对并修改比较条件 | 登录/验证应交本人处理；费用和规则属于同一门店来源；核对已知小计与条件优惠；套餐不能直接均摊认定够用；如选择优惠，先明确核对对应分店与地址；请求的比较、时段或路线问题未回答应记缺项 |
| 3. 中断后继续 | 在草案已保存、没有进行中操作时关闭桌面；重新打开，从历史进入原任务；修改一个条件并保存 | 原任务、人数/日期/预算、已选优惠和历史回复保留；恢复本身不新增模型轮次；新修改产生独立回复与版本 |

遇到发送失败，先使用界面的“核对送达并取回”；确定未送达才按原请求继续。不要复制成新任务补成功，不重放结果未知的页面操作。

这轮不要求预约提交、下单、付款或给商家发消息。找不到真实网页表单属于能力边界，应记“未覆盖”；App-only菜单/规则不足应记“部分读取”，不能记为完整业务完成。
